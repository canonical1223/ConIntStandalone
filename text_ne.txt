План работ на 20 рабочих дней
План распределён на 20 дней с учётом приоритетов, зависимостей между задачами и необходимости проверки результатов. Для каждой задачи указаны три обязательных подпункта: проблема, действие и результат. Актуализация документации выполняется на протяжении всего периода параллельно с основной разработкой.

День 1. Python API — анализ текущей реализации
Задача: Провести анализ текущей структуры Python API и определить проблемы установки, упаковки и кроссплатформенной сборки.
	•	Проблема: Текущая реализация Python API требует доработки механизмов установки, упаковки и сборки на разных платформах. Необходимо определить существующие ограничения и выявить проблемные участки конфигурации.
	•	Действие: Изучить структуру проекта, CMake-файлы, конфигурации сборки и механизм подключения Python API. Зафиксировать текущие сценарии сборки и установки, выявить зависимости от конкретной среды.
	•	Результат: Подготовлен перечень проблемных участков и определена последовательность доработок Python API.
День 2. Python API — настройка установки
Задача: Настроить механизм установки Python API и проверить корректность размещения устанавливаемых компонентов.
	•	Проблема: Установка Python API может зависеть от текущего окружения и существующих путей сборки, что затрудняет воспроизводимое развёртывание.
	•	Действие: Проверить и скорректировать правила установки, размещение модулей и необходимых файлов, обработку путей и зависимостей. Выполнить тестовую установку в отдельном каталоге.
	•	Результат: Подготовлен и проверен механизм установки Python API в соответствии со структурой проекта.
День 3. Python API — упаковка
Задача: Настроить формирование пакета Python API и проверить его пригодность для последующего использования.
	•	Проблема: Без согласованного механизма упаковки сложно обеспечить переносимость компонентов и повторяемость установки в целевых окружениях.
	•	Действие: Проверить состав пакета, правила включения файлов, метаданные, зависимости и конфигурацию сборки пакета. Устранить обнаруженные несоответствия.
	•	Результат: Подготовлен механизм упаковки Python API, определён состав пакета и выполнена его тестовая сборка.
День 4. Python API — кроссплатформенная сборка
Задача: Адаптировать конфигурацию Python API для сборки в различных поддерживаемых окружениях.
	•	Проблема: Конфигурации и пути, рассчитанные на одну операционную систему или среду разработки, могут препятствовать сборке на других платформах.
	•	Действие: Проверить платформозависимые участки CMake-файлов, настройки компилятора, пути к зависимостям и условия выполнения команд. Скорректировать обнаруженные ограничения.
	•	Результат: Подготовлена кроссплатформенная конфигурация сборки Python API и выполнена проверка доступных целевых окружений.
День 5. Python API — сборка при выключенной документации
Задача: Устранить ошибку сборки Python API при отключённой генерации документации.
	•	Проблема: При выключенной документации сборка завершается ошибкой, что указывает на некорректную зависимость сборочных целей от документации либо на неправильную обработку соответствующих параметров.
	•	Действие: Проанализировать условия создания целей и зависимостей в CMake. Проверить обработку флагов сборки документации и исключить обязательное выполнение документационных этапов при их отключении.
	•	Результат: Python API успешно собирается при отключённой документации; проверена корректность работы соответствующего параметра конфигурации.
День 6. Python API — устранение захардкоженных значений
Задача: Выявить и устранить жёстко заданные значения в конфигурациях и CMake-файлах Python API.
	•	Проблема: Захардкоженные пути, версии, параметры окружения и другие значения затрудняют сопровождение проекта и перенос сборки в другие среды.
	•	Действие: Провести поиск фиксированных значений, определить, какие из них должны задаваться через переменные, параметры конфигурации или механизмы автоматического определения. Заменить их подходящими параметрами и проверить использование в зависимых целях.
	•	Результат: Устранены выявленные необоснованные жёстко заданные значения, повышена гибкость конфигурации проекта.
День 7. Python API — рефакторинг и проверка
Задача: Завершить рефакторинг CMake-файлов и конфигураций Python API, проверить совместимость внесённых изменений.
	•	Проблема: Локальные исправления не гарантируют согласованности всей конфигурации и могут приводить к повторению логики или регрессиям.
	•	Действие: Систематизировать изменённые правила сборки, устранить дублирование, проверить условия платформенной сборки, установки и упаковки. Выполнить контрольные сборки с документацией и без неё.
	•	Результат: Проведён рефакторинг конфигураций Python API, проверены основные сценарии сборки и установки, зафиксированы оставшиеся ограничения при их наличии.

День 11. Диалог загрузки маркеров — анализ интеграции

	•	Действие: Изучить механизм вызова справки из существующих диалогов, определить точку обработки нажатия F1 и установить соответствие между диалогом загрузки маркеров и необходимой страницей справки. Учесть основание — оперативное поручение письмом от 20.10.

	•	Действие: Реализовать обработку F1 в соответствии с архитектурой приложения, настроить идентификатор или путь соответствующей страницы справки. Проверить открытие нужного раздела и обработку возможных ошибок.
	•	Результат: В диалоге загрузки маркеров реализован вызов справки по F1, проведена проверка перехода к соответствующему материалу.

	•	Действие: Изучить структуру справочных материалов, определить используемые форматы, состав глав и разделов, выявить отсутствующие и дублирующиеся материалы. Подготовить перечень соответствий между окнами программы и разделами справки.
	•	Результат: Подготовлен перечень исходных материалов, определены требования к преобразованию и сформирована основа таблицы соответствий.

	•	Результат: Сформирована таблица соответствий «окно программы — раздел справки», определены пробелы, препятствующие реализации интерактивности.
День 15. Интерактивная документация — подготовка форматов DrExplain и QCH
Задача: Переработать и подготовить справочные материалы для использования в форматах DrExplain и QCH.

	•	Действие: Подготовить структуру глав и разделов, проверить ссылки, идентификаторы и навигацию. Выполнить преобразование или настройку сборки материалов для DrExplain и QCH с учётом возможностей используемых инструментов.

	•	Результат: Подготовлен инструмент расчёта покрытия справки и определены критерии оценки полноты документирования.

	•	Действие: Сформировать перечень учитываемых функций и окон программы, применить разработанный инструмент, проверить корректность сопоставлений. Разделить документированные функции, функции с неполным описанием и функции без соответствующих материалов.
